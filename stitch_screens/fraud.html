Why Does This Work?

bug_report

Standard Mode Flaw: Second-Preimage Equivalence

In naive Merkle trees, the formula for calculating an internal node is SHA256(left || right), which has the identical input structure as hashing an arbitrary 64-byte payload. Because verifiers do not distinguish between leaf nodes and internal routing nodes, an attacker can submit an entire internal branch hash as if it were a genuine delivery package, reducing the required proof depth by 1 and draining package balances.

Verify(leaf, proof) => Root evaluates to TRUE without verifying leaf semantic type!
security

Two SafeDrop Mitigations (RFC-6962 Standard)

SafeDrop eliminates preimage ambiguity by prepending distinct single-byte domain prefixes before each cryptographic operation:

  • verified 1. Domain Byte Tagging: Package leaves are calculated as SHA256(0x00 || data), while internal routing nodes use SHA256(0x01 || left || right). An internal hash can never produce a valid leaf prefix.
  • verified 2. Strict Depth Parity: The smart contract verifier enforces that Merkle proof depth must strictly equal manifest tree depth log₂(Leaves), preventing truncated path submissions.
